## Scope

## الشرح قبل التنفيذ

الاستجابة 204 بلا body أو Cookies لكل طلب تسجيل صحيح البنية، سواء كانت المعرّفات متاحة أو مستخدمة أو محجوزة؛ لا يكشف وجود الحساب. قبول الشروط إلزامي ويسجل وقت UTC؛ لا يخترع النظام نصًا قانونيًا أو يدعي نسخة منشورة لم تقدم. كلمة المرور 15–128 Unicode rune، دون تركيب إجباري، مع قائمة صغيرة للكلمات الشائعة لا تدعي تغطية كلمات مسربة أو امتثال NIST. شرح الكود التفصيلي بعد التسليم.

## تسلسل التنفيذ

تحقق Pipeline من المدخلات، ثم معاملة SQL وقفلَي المعرّفات HMAC بترتيب ثابت، وإنشاء المستخدم عبر UserManager، وإضافة MerchantAccount عند مسار التاجر، ثم Commit. أي فشل بعد SaveChanges داخل store أو Merchants يرجع المعاملة. تفرد SQL داخل AccountType؛ أعمدة Normalized لها مقارنة BIN2 لتتطابق مساواة التخزين مع مدخل HMAC المطبع. حجز دائم بعد الحذف يستخدم جدول بصمات دون البيانات الأصلية؛ يكتب في S09 في معاملة purge نفسها، مع الأقفال نفسها، ولا يحتاج إعادة حساب أسرار داخل Migration.

أول إعادة للحل: 47 Architecture و16 Unit ناجحة؛ Integration =91 passed و1 failed، بلا skipped. فشل اختبار migration عند GetCollation على read-optimized model بعد نجاح الترحيل وحفظ الصف وكلمة المرور؛ صُحح الفحص ليقرأ sys.columns الفعلية، دون تقليل assertion أو تغيير Migration. التسجيل والتفرد والتنافس وrollback عبر HTTP نجحت في تلك الإعادة. وُحد تحقق البريد في Domain للمسارات العامة وIdentity وbootstrap؛ يرفض DisplayName ومحارف التحكم دون DNS/SMTP. لا S04 قبل إعادة النجاح.
