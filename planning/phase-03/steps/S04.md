## الهدف والسبب

استيراد الأنشطة الأربعة والنسخة الجغرافية المعتمدة بمفاتيح مصدر مستقرة، دون تكرار أو إعادة كتابة تعديل Admin أو تعطيله أو حذفه عند إعادة التشغيل.

## مصادر واعتمادات

[S03](S03.md) Verified بعد319 اختبارًا و[تسليمها](../handoffs/S03-to-S04.md) InternalReady. D018 وD019 والنسخة الجغرافية76b47b22872288c0d8b0c757975980e6986945e8. أسماء الأنشطة العربية من المتطلبات المعتمدة، والقيم الإنجليزية ترجمة عرض للمعاني نفسها دون إنشاء أنشطة أخرى.

## Scope

أمر CLI صريح، ومصدر جغرافي مثبت ومضمّن مع الترخيص والنسب والبصمات، وعقد Catalog عام للاستيراد داخل معاملة واحدة مع Locations. سجلا مفاتيح استيراد مملوكان للوحدتين يحفظان الربط والتاريخ حتى إذا حذف Admin عنصرًا؛ لا Audit عام أو تغيير للحسابات أو تشغيل تلقائي عند بدءHTTP.

## الشرح قبل التنفيذ

SourceKey أساس اكتشاف الاستيراد السابق. Receipt تحتفظ بمعرف الصف ولا ترتبط به FK عمدًا كي لا تعيد Seed إنشاء صف حذفه Admin. المعرفات Guidv7 تنشأ مرة واحدة وتبقى مستقرة، وأسماء المصدر لا تستخدم هوية أو تعاد صياغتها لتجاوز تكرار الإنجليزية. لا تحديث لأي صف سبق ربطه بالمصدر. إذا تعارضت أسماء نشاط موجودة قبل أول استيراد، يفشل الاستيراد دون استبدالها؛ تطابق الاسمين كاملًا يسمح بتبني الصف مع حفظ حالته.

## تسلسل التنفيذ

التحقق منSHA256 ونسخة المصدر والأسماء والعلاقات والأعداد قبل أي كتابة، ثم معاملة واحدة: قفلCatalog واستيراد أنشطته عبر العقد العام، ثم قفلLocations واستيراد المحافظة ثمCity ثمArea وسجلات مفاتيحها. Commit واحد بعد الجميع؛ خطأ بعد حفظ الآباء يرجع كل الوحدتين. لا حذف أو إعادة إنشاء قاعدة أوVolumes.
