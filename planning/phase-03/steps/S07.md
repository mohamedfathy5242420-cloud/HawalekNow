## الهدف والسبب

تقليل SQL لقراءات الاختيار العامة الفعلية في Catalog و Locations دونتخزين حسابات أوصلاحيات أو Entities أوتوسيعنطاق Search.

## Scope

عقد Cache تقني ذو Snapshot immutable محددةمن Guid/Name وصفحة فقط داخل Application.Shared.Caching، وتنفيذ IMemoryCache خاص في Infrastructure.Shared.Caching. Decorators مملوكة لكلوحدة تستهلك خدمات قراءتها الفعلية؛ الإدارة تتجاوز Cache. لا تجريد object عام يمكنه حمل Entities.

## الشرح قبل التنفيذ

المفتاح يحدد Family/resource/language/owner/parent/page/pageSize/activeOnly. عمر 60 ثانية وحد 8192 وحدة حجم، تكلفةالصفحة 1+عددعناصرها وبحد 100 عنصر، دونتقييدذاكرة framework العامة. كل family لها generation؛ lookup و capture و publish و invalidate تحتقفل قصير، و SQL خارجالقفل. loader قديم يمكنه إكمالطلبه لكنه لايملأجيلًا جديدًا بعدالإبطال. لا نتيجةفشل مخزنة. Entries منأجيالسابقة تنتهي بالعمر وتظلداخلالحد.

## تسلسل التنفيذ

تسجيل Singleton واحد عبر TryAdd لكل Host، و Decorators تعيد DTOs الوحدة immutable. mutations تبطل family بعد Commit الناجح فقط؛ رفض أو rollback لايبطلان. Seed تبطل Catalog عبرعقده و Locations بعد Commit المشترك فقط. CLI له Host مستقل، لذلك يشغّل قبل HTTP أوينتظر TTL لل Hosts القائمة؛ لااتساقبينالنسخ.
