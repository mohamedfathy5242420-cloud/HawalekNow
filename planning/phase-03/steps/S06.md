## الهدف والسبب

تأسيس GeoPoint بحدود صحيحة وتحويل SQL geography SRID4326 للمستهلك الإنتاجي المحدد في ROADMAP P04-S04، الفروع ونقاط الاستلام، ثم حساب المسافة في Search لاحقًا.

## مصادر واعتمادات

[توثيق EF الرسمي](https://learn.microsoft.com/en-us/ef/core/modeling/spatial) و[SQL STDistance](https://learn.microsoft.com/en-us/sql/t-sql/spatial-geography/stdistance-geography-data-type?view=sql-server-ver17).

## Scope

Domain.Shared.Geography قيمة immutable دون EF/NTS؛ Infrastructure.Shared.Geography تملك التحويل وتسجيل مزود NTS. لا centroid فيLocations أوSeed أوفرع أوجدولProbe أوendpoint إنتاجي أوMaps أوبحث1000متر. صحح [التصميم](../DESIGN.md) افتراض centroid قبل الكود من المراجع.

## الشرح قبل التنفيذ

Latitude بين-90 و90 وLongitude بين-180 و180 شاملًا؛ كلتاهما finite. NTS تستخدم X=Longitude وY=Latitude، بينما SQL geography::Point تستقبل Latitude ثمLongitude. لا تستخدم NTS Distance العميلية لحساب أمتار؛ SQL STDistance على4326 تعطي مترًا. اختبار معروف من(0,0) إلى(0,1) نحو111319.49متر، بسماحية300متر تعكس حد تقريب SQL الموثق0.25%.

## تسلسل التنفيذ

GeoPoint والتحويل مع رفض نقطة فارغة أوSRID مخالف. تثبيت Microsoft.EntityFrameworkCore.SqlServer.NetTopologySuite10.0.14 وNetTopologySuite2.6.0 داخلInfrastructure فقط، ومراجعة تراخيص MIT/BSD-3-Clause منNuGet الرسمي وملفاتnupkg. تسجيل NTS في مساريPersistence ومصنع التصميم. اختبار DbContext نفسه مع ModelCustomizer معزول يضيف نوعًا فيالاختبار فقط إلىجدول اختبار داخلقاعدته، ثمEF roundtrip وSQL metadata/axes/distance/invalidSRID. لا Migration إنتاجية بلا حقل مطلوب.
